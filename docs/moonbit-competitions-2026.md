## 2. 十一月赛详解

### 2.1 赛季历

```
8月 ─ 10月 : Q1
11月 ─ 次年1月 : Q2  ← 现在在这里（2026-11-01 开始）
2月 ─ 4月   : Q3
5月 ─ 7月   : Q4
半年：8月–次年1月 / 2月–7月
年度：8月–次年7月
```

### 2.2 参赛流程（五阶段）

| 阶段 | 时间 | 要做的事 |
| --- | --- | --- |
| 01 报名申报 | 报名开放后（**未公布具体日期**） | 飞书表单提交参赛信息 + 公开仓库 + 一页项目说明 |
| 02 资格审核 | 滚动审核 | 以「通过审核前最后一次有效提交/修改」时间为准；未通过可改 |
| 03 集中开发 | 本期赛季内 | 公开持续提交，保留 Issues、PR、更新记录 |
| 04 项目验收 | 官方通知 | 交代码、README、测试、可复现演示说明 |
| 05 季度评选 | 每季度一次 | 当季新项目 + 主动报名的社区维护项目，同一池评选 |

### 2.3 季度评选的两条路径

1. **月度新项目**：本月完成开发并通过验收 → 自动进入当季评选。
2. **社区维护项目**：已在维护 MoonBit 生态项目的人可主动报名，不要求当季新建、不要求个人独立完成（需可追溯的实质贡献）。

季度/半年度/年度奖金分别评定，可叠加；月度支持在审核/验收通过后发放。

### 2.4 组队与报名规则

- 沿用原有报名表（飞书），队长统一确认人数与成员 GitHub ID。
- 2 人队每人 1/2，3 人队每人 1/3。
- **必须加入赛事微信群**，并把群昵称改成自己的 GitHub ID，否则影响奖金发放。
- 可维护非本人创建的旧项目（含 MoonBit 官方项目），但要有可追溯贡献记录。

### 2.5 奖励结构（原文口径）

| 周期 | 奖项 | 金额 | 名额 |
| --- | --- | --- | --- |
| 月度 | 启动支持 | 150 元 | 审核通过即发 |
| 月度 | 完成支持 | 350 元 | 验收通过后发 |
| 季度 | 一等奖 | 12,000 元 | 1–2 名 |
| 季度 | 二等奖 | 6,000 元 | 3–4 名 |
| 季度 | 三等奖 | 3,000 元 | 5 名 |
| 季度 | 奖金池 | 80,000 元 | 全部得主合计 |
| 半年度 | 一等奖 | 24,000 元 | 另行评定 |
| 年度 | 一等奖 | 36,000 元 | 另行评定 |
| 推荐 | 50 元/人 | 上限 5 人 | 需被推荐人填推荐人 GitHub ID |

> ⚠️ **口径不一致，需向赛事组确认**：按上表季度单项金额与名额上限计算，季度合计为 12,000×2 + 6,000×4 + 3,000×5 = 63,000 元，与官网写的「季度奖金池总计 80,000 元」对不上。奖金以正式章程/审核结果为准，不要用 80,000 反推人均。

### 2.6 验收标准（六条，逐条可自检）

| # | 标准 | 自检方式 |
| --- | --- | --- |
| 1 | MoonBit 为主实现语言 | 仓库语言统计中 MoonBit 占主体；外围脚本不计入 |
| 2 | 仓库公开、提交连续可追踪 | 从第一天起 public，别最后一次性 push |
| 3 | 能够运行 | README 有 quickstart，`moon run` / `moon test` 一条命令跑通 |
| 4 | 工作有效 | 已有项目必须有本期实质新增；移植需说明来源与许可 |
| 5 | 开源合规 | OSI 许可（Apache-2.0 / MPL-2.0 / MIT 等），移植要标注 upstream license |
| 6 | AI 可解释 | 说清用了什么 AI、生成/人改比例、如何验证；作者能解释设计取舍 |

**明确排除**：重复提交、拆分项目、仅做简单修改。

### 2.7 方向（启发，非限制）

- 工具库：通用工具、协议库、可复用基础组件
- 数据处理：数据处理、数据库、分析、内容处理
- AI 应用：结合 AI 解决真实需求的开源应用
- 开发者工具：解释器、运行时、LSP、CLI

选题落点见 [`topic-shortlist.md`](./topic-shortlist.md)。

## 4. 参赛合规清单

仓库层：

- [ ] 公开仓库，从第一天起有连续 commit（不要最后一次性提交）
- [ ] README：项目目标、功能边界、quickstart、目录结构、测试方式、许可证
- [ ] LICENSE 文件（OSI 认证）；移植项目在 README 标注 upstream 与许可证
- [ ] `moon test` 全绿；关键路径有集成测试；示例数据随仓库提供
- [ ] Issues/PR 有真实使用痕迹（评审会看开发过程）

赛事层：

- [ ] 飞书表单提交：参赛信息 + 仓库地址 + 一页项目说明（**表单是否要推荐人 GitHub ID：按需填写**）
- [ ] 加入赛事微信群，群昵称 = GitHub ID
- [ ] 队长确认队伍人数（≤3）与其他成员 GitHub ID
- [ ] 验收材料：代码 + README + 测试 + 可复现演示说明

内容层：

- [ ] 已说明 AI 使用方式与验证手段（哪些是 AI 生成、人怎么审、怎么测）
- [ ] 有「本期新增」的清晰边界（尤其复用已有项目时）

## 6. 常见问题

**Q：可以用 AI 写代码吗？**
可以。官方多次强调「这不是提示词比赛」：AI 可参与代码、接口、测试、文档，但参赛者必须能解释技术选择并对最终质量负责。

**Q：项目必须很大吗？**
不必。官方原话：「比起堆叠功能，我们更看重清晰边界、可靠测试、完整文档和真实可用性。」

**Q：能交已有项目吗？**
能，包括维护别人创建的项目（如官方项目）。但只计算本期新增的实质工作，重复/拆分/简单改不算。

**Q：奖金能叠加吗？**
能。季度、半年度、年度分别评定，三个一等奖合计 72,000 元（12,000 + 24,000 + 36,000）。月度支持另算。

**Q：个人能参加吗？**
能。单人成队；SCC 那种"仅个人赛"是另一个赛事，已结束。

**Q：一定要进微信群吗？**
官网写明「参赛选手必须加入赛事交流群，并将群昵称改为自己的 GitHub ID，否则将影响奖金发放」。

**Q：十一月赛的截止日期？**
官方未公布，页面只写"以官方通知为准"。建议按 §3 的自定节奏推进，并盯官网/群公告。
