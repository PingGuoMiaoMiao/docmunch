# P12 检索升级：BM25

- 时间：2026-11-12
- 背景：`docs/reference-comparison.md` 把「检索只有加权打分，没有 BM25」列为 P0 短板
- 结论：**默认检索已换成 BM25**，旧的加权打分保留为 `--mode weighted`；98 个测试全绿

## 1. 为什么换

旧的加权打分是手写的整数加分（标题 +20/+10/+5、路径 +2、正文词 +1 封顶 5），它有两个结构性问题：

1. **没有词频与逆文档频率**：一个词在 8 个小节里都出现，和只出现 1 次，得分一样；
2. **没有长度归一化**：长小节天然更容易命中多个词，短小节被系统性低估。

BM25 正好补这两点。实测同一查询（`document cloneNode`）在 readability 文档上的分布：

| 模式 | 得分分布 |
| --- | --- |
| 旧加权 | 6 / 6 / 1 / 1 —— 前两名并列，无法区分 |
| **BM25** | 89 / 87 / 63 / 63 —— 有梯度，且稀有词权重更高 |

## 2. 实现

`index/search.mbt` 重写，参数与参考实现对齐：`k1 = 1.2`、`b = 0.75`。

```
score(s, Q) = Σ_{t ∈ Q} idf(t) · tf_w(t) · (k1 + 1) / (tf_w(t) + k1 · (1 - b + b · len/avg_len))

idf(t)  = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
tf_w(t) = 3·tf(title) + 2·tf(path) + 1·tf(body)
len     = body tokens + 3·title words + path words
```

三点工程取舍：

- **词频存在索引里，不在检索时读原文**：`Section.terms` 是「按词频重复展开的字符串数组」（最多 40 个词、单次最多重复 8 次），`Section.tokens` 记录本节合格 token 总数。用 `Array[String]` 而不是 `Map` 是因为它天然可 JSON 派生，不需要自定义编解码。
- **平均长度每次查询现算**：`Σ len / N`，O(节数) 的整数加法，不引入额外字段，也不会因索引重建而失效。
- **两种模式共存**：`search_with_mode(index, query, mode)`，`search()` 默认 BM25；CLI 用 `--mode`，MCP 的 `search_sections` 用 `mode` 参数。

## 3. 兼容性

索引格式变了（`keywords: Array[String]` → `terms: Array[String]` + `tokens: Int32`），因此 `index_version` **2 → 3**。旧索引加载时 fail-closed 返回「未索引」，下次 `index` 自动重建，不需要手工清理。

## 5. 已知限制

- 中文没有分词，`terms` 只收 ASCII 词；中文查询仍主要靠标题与路径命中（与 P8 的限制一致）；
- 没有停用词之外的词干化（`documents` 与 `document` 不合并）；
- 没有 posting list 缓存，每次查询扫描全部小节——文档量在千级以内时开销可忽略（单次查询仍在毫秒级），上万小节时需要倒排索引。
